# Ограничения и план развития

## Текущие ограничения (кратко; подробно — `assumptions.md`)
- **Стрелки на конечных**: выбор пути на многопутной конечной ненаблюдаем без курса —
  локально до ~50 м ошибки положения (проверочный bag, последние 60 с).
- **Износ колёс между ориентирами**: общий масштаб одометрии оценивается только через
  привязки к остановкам; до первой привязки дрейф определяется калибровкой (σ ≈ 0.2 %,
  отдельные вагоны до 1.5 %).
- **Одновременная пробуксовка обеих тележек** с правдоподобным ускорением принимается за
  движение.
- **Масса и сила** — в удельных единицах; абсолютные величины зависят от номинальных
  параметров вагона.
- Прогон в гарнессе жюри (ROS 2 Humble, Docker) пройден: скорость 0.0285 м/с, положение
  6.15 м, CPU ≈ 1.1 %, RSS ≤ 36 МБ, задержка p95 0.7 мс (max 6 мс); на целевом бортовом
  железе замер нужно повторить.

## План развития после хакатона
1. **Графовая карта с развилками** (вместо одной замкнутой полилинии): несколько гипотез
   пути после стрелки (multi-hypothesis / particle filter по рёбрам) и выбор по
   косвенным признакам — длине до следующей остановки, профилю скорости в кривой
   (ограничения скорости на стрелках), месту остановки.
2. **Кривые и уклоны из карты**: сопротивление в кривых $\propto$ кривизне (`curv` в
   pathgraph) и уклон из `z` карты как известные члены динамики вместо возмущения $d$ —
   точнее модель при отказе обеих тележек.
3. **Ориентиры не только по остановкам**: характерные профили скорости (стрелки, кривые
   с ограничением скорости), кривизна как «сигнатура» пути для map-matching.
4. **Полная IMM** с отдельными фильтрами на режим и смешиванием состояний; пороги и
   матрица переходов — обучение по размеченным эпизодам (разметка по GNSS офлайн).
5. **Модель сцепления** Pacejka/Kalker для пары колесо–рельс с оценкой λ₀ и μ по
   эпизодам пробуксовки; связь μ с погодой (внешние данные).
6. **Идентификация по вагонам**: отдельные калибровки масштаба колёс/характеристики по
   бортовому номеру, хранение адаптированных параметров между поездками.
7. **Residual learning**: небольшая модель (GBM/NN) поверх физической для остаточного
   ускорения (калибровка только на разрешённых данных), с контролем интерпретируемости.
8. **Интеграция**: `tf` map→base_link, `robot_localization`-совместимые ковариации,
   `ros2_control`/real-time executor, сертификационная документация (FMEA по режимам).
9. **Инфраструктура**: CI со сборкой в `ros:humble-ros-base`, прогон реплеера по всему
   датасету как регрессионный тест точности, ASan/UBSan-сборка (`-DTRAM_ODOMETRY_SANITIZE=ON`)
   в CI и долгий soak-тест.
