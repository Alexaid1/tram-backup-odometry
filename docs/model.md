# Математическая модель резервной одометрии трамвая

Документ описывает всю цепочку «ручка контроллера + скорости тележек → скорость и положение»,
реализованную в пакете `tram_odometry` (ядро: `ros2_ws/src/tram_odometry/src/core/`).
Все численные значения параметров — в `config/params.yaml`; помеченные `[calib]` получены
офлайн-калибровкой по датасету (`tools/calibrate.py`, `tools/calib_arclen.py`).

## 1. Модель тягового привода (1.1)

Выбран **вариант (c) — гибрид**: аналитическая форма тяговой/тормозной характеристики с
параметрами, откалиброванными нелинейным МНК по датасету, + онлайн-адаптация
коэффициентов эффективности RLS. Обоснование: аналитическая форма физически
интерпретируема (зона постоянной силы → зона постоянной мощности, отсутствие «толкания»
тормозом на стоянке), имеет 9 параметров вместо сотен ячеек LUT (нет переобучения,
тест ≈ обучение), и экстраполирует разумно за пределы данных.

Работаем в **удельных силах** (на единицу номинальной массы, м/с²): масса трамвая в данных
не измерена, поэтому сила и момент выводятся для диагностики через `model.mass_kg`,
радиус колеса и передаточное число.

**Запаздывание привода** (контроллер → тяговый преобразователь → момент):

$$\dot u_f = \frac{u - u_f}{\tau_{drive}}, \qquad \tau_{drive} = 0.3\ \text{с}\ [calib]$$

Дискретно: $u_f \leftarrow u_f + (1 - e^{-\Delta t/\tau})(u - u_f)$.

**Тяга** ($u_f > u_{dz}$, $u_{dz} = 0.5$ — мёртвая зона):

$$a_{tr}(u_f, v) = A_t \left(\frac{u_f}{15}\right)^{\gamma_t} \cdot \frac{1}{\left(1 + (v/v_b)^p\right)^{1/p}}$$

- $A_t = 1.50$ м/с² — максимальная удельная сила тяги [calib];
- $\gamma_t = 0.82$ — форма зависимости от позиции ручки [calib];
- второй множитель $g(v)$ — **насыщение по скорости**: при $v \ll v_b$ ≈ 1 (постоянная
  сила, ограничение по току), при $v \gg v_b$ ≈ $v_b / v$ (постоянная мощность,
  ослабление поля ТЭД); $v_b = 5.45$ м/с (19.6 км/ч), $p = 2.89$ — гладкость перехода [calib].

**Торможение** ($u_f < -u_{dz}$):

$$a_{br}(u_f, v) = -A_b \left(\frac{|u_f|}{15}\right)^{\gamma_b} \tanh\!\left(\frac{v}{v_\varepsilon}\right)$$

$A_b = 1.21$ м/с², $\gamma_b = 0.58$ [calib]; $\tanh(v/v_\varepsilon)$, $v_\varepsilon = 0.3$ м/с —
тормоз не разгоняет трамвай назад на стоянке (сила трения покоя).
Разная динамика тяги и торможения отражена разными $A, \gamma$ и отдельными
коэффициентами адаптации.

**Адаптированное ускорение привода** и переход к моменту:

$$a_{drive} = \kappa_t\, a_{tr} + \kappa_b\, a_{br}, \qquad
F = m\, a_{drive}, \qquad M_{motor} = \frac{F\, r_w}{i\, n_{motors}}$$

$\kappa_t, \kappa_b$ ≈ $m_0/m_{eff}$ — отношение номинальной массы к текущей эффективной
(пассажиропоток, инерция вращающихся масс, износ); оцениваются онлайн (см. 1.1.1).
$F$ и $M_{motor}$ публикуются в `/diagnostics` (`traction_force_N`, `motor_torque_Nm`).

**Ограничение по сцеплению** (часть модели проскальзывания, 1.3):

$$a_{drive}^{lim} = \mu g k_{adh} \tanh\!\left(\frac{a_{drive}}{\mu g k_{adh}}\right)$$

— гладкое насыщение: тяговое/тормозное усилие, передаваемое на рельс, не превышает
$\mu N$; $\hat\mu$ — компонент вектора состояния.

### 1.1.1 Онлайн-адаптация (RLS)

В условиях доверия (обе тележки в режиме grip с вероятностью > 0.8, v > 1 м/с) для каждого
режима (тяга/торможение) выполняется скалярный RLS с забыванием $\lambda = 0.9995$
(память ≈ 2000 обновлений ≈ 3 мин):

$$y = \hat a - \hat d + r(v), \quad \varphi = a_{tr}\ \text{или}\ a_{br}$$
$$K = \frac{P\varphi}{\lambda + \varphi^2 P},\quad \kappa \leftarrow \kappa + K(y - \kappa\varphi),\quad
P \leftarrow \frac{P - K\varphi P}{\lambda}$$

$\hat a$ — ускорение оценки скорости, сглаженное ФНЧ (τ = 0.5 с); $\kappa \in [0.6, 1.6]$;
обновление только при $|\varphi| > 0.15$ (информативный регрессор).

### 1.1.2 Калибровка по данным

`tools/calibrate.py`: 88 уникальных прогонов, 10 Гц сетка; ускорение — производная
Савицкого–Голея согласованной скорости тележек (|front − rear| < 0.1 м/с). Нелинейный МНК
(soft-L1) по 3/4 прогонов, проверка на отложенной 1/4 прогонов; τ подобран перебором.

| | RMS ошибки ускорения |
|---|---|
| обучение (66 прогонов) | 0.222 м/с² |
| тест (22 прогона) | 0.207 м/с² |
| СКО самого ускорения | 0.550 м/с² |

Модель объясняет ≈ 86 % дисперсии ускорения только по ручке и скорости; остаток
(уклоны, масса, погода) — это возмущение $d$ и адаптация $\kappa$.

**Замеченное ограничение** (docs/figures/traction_model.png): на участках, где ручка
неподвижна ≥ 2 с, ускорение ниже открытой характеристики (позиция 3 → a ≈ 0, позиция −8 →
a ≈ −0.2 м/с²). Вероятная причина — замкнутый контур «водитель»: позицию удерживают, когда
поддерживают скорость на уклоне, т.е. эти участки смещены отбором; характеристика
идентифицирована в основном по переходным процессам, а разницу несёт возмущение $d$.
Гипотеза не доказана — уточнение идентификации в плане развития.

## 2. Продольная динамика (1.2)

$$\dot v = a_{drive}^{lim}(u_f, v) - r(v) + d, \qquad \dot s = k_{arc}\, v$$

- **Сопротивление движению** (удельное, основное + аэродинамическое):
  $r(v) = (c_0 + c_1 v + c_2 v^2)\tanh(v/0.1)$, $c_0 = 0.053$ м/с², $c_1 = -0.0058$ 1/с,
  $c_2 = 2.8\cdot10^{-4}$ 1/м [calib]. $\tanh$ — сопротивление не действует на стоянке.
  Небольшой отрицательный $c_1$ компенсирует корреляцию с $c_2$ на диапазоне 0–15 м/с.
- **Уклон и неучтённые силы** — медленно меняющееся возмущение $d$ (состояние фильтра,
  модель Орнштейна–Уленбека): $\dot d = -d/\tau_d + w_d$, $\tau_d = 30$ с. На стоянке
  $d$ ненаблюдаемо (сила трения покоя) и релаксирует к 0 с τ = 1 с — иначе при трогании
  фильтр «помнит» уклон предыдущего перегона (найдено на проверочном bag).
- Сопротивление в кривых входит в $d$ (кривизна пути известна из карты — план развития).
- **Скольжение** входит через ограничение по сцеплению и через модель измерений (разд. 3).
- $k_{arc} = 1.00043$ [calib] — отношение длины дуги карты к пройденному по одометрии
  пути (65 участков, σ = 0.19 %).
- $v \ge 0$ (трамвай в линейной эксплуатации не движется назад; датчики беззнаковые).

**Дискретизация**: явный Эйлер для $v$ с шагом ≤ 50 мс, трапеция для $s$:
$v_{k+1} = \max(0, v_k + a\Delta t)$, $s_{k+1} = s_k + k_{arc}\tfrac{v_k + v_{k+1}}{2}\Delta t$.

**Способ оценки ускорения**: ускорение не измеряется; в predict используется модельное
$a$ (ручка + динамика), в выходе/диагностике — сглаженная производная апостериорной
оценки скорости.

## 3. Модель проскальзывания и измерений тележек (1.3)

**Скольжение** тележки $i \in \{f, r\}$:

$$\lambda_i = \frac{\omega_i r_{eff} - v}{\max(v, \varepsilon)} = \frac{z_i - \hat v}{\max(\hat v, 0.5)}$$

($z_i = \omega_i r_{eff}$ — показание датчика в м/с). Публикуется в `/result/slip_status`.

**Модель измерения** (с учётом износа и задержки сообщения):

$$z_i = (1 + b_i + c)\,\bigl(v - \hat a\,\ell_i\bigr) + \eta_i, \qquad
\eta_i \sim \mathcal N\bigl(0,\ \sigma_{abs}^2 + (\sigma_{rel} v)^2\bigr)$$

$b_i$ — относительная ошибка масштаба отдельной тележки, $c$ — общая ошибка масштаба
одометрии (износ бандажей), $\ell_i$ — запаздывание сообщения относительно времени фильтра
(сообщения тележек приходят в среднем на 40 мс позже своего штампа).

**Связь силы сцепления со скольжением** (упрощённая «линейно-насыщающаяся» кривая
вместо полной Magic Formula — параметров Pacejka для пары колесо–рельс из данных не
идентифицировать): $F_{adh} = \mu N\, \tanh(\lambda / \lambda_0)$. При малых $\lambda$ сила
передаётся полностью (режим grip, $z_i \approx v$), при больших — насыщается на $\mu N$
(режим slip): колесо «отрывается» от скорости трамвая, а ускорение трамвая ограничено
$\mu g$. Поэтому в фильтре: (а) ограничение $a_{drive}$ по $\hat\mu g$ (разд. 1),
(б) в режиме slip измерение тележки теряет вес, (в) $\hat\mu$ оценивается (разд. 4.3).

### 3.1 Признаки проскальзывания/аномалий (свидетельства для IMM)

Каждое сообщение тележки даёт невязку $y_i = z_i - \hat z_i$ и набор эвристических
множителей правдоподобия гипотез (пороги в `slip.*`):

| # | Признак (требование кейса) | Условие | Эффект |
|---|---|---|---|
| 1 | датчик залип / отказ | $z_i < 0.05$, другая тележка свежая и $> 0.5$ м/с, не торможение | $L_{fault}\times50$, $L_{grip}\times0.01$ |
| 2 | резкий рост ω без роста v | $\lvert\dot z_i\rvert > 2.5$ м/с² (физически невозможно для трамвая) | $L_{slip}\times10$ |
| 3 | рассогласование тележек | $\lvert z_f - z_r\rvert > 0.3 + 0.05v$, виновата тележка с большей невязкой | $L_{slip}\times5$ |
| 4 | высокий тяговый момент при низкой производной скорости / отрицательное рассогласование при торможении (юз) | тяга ($u_f>1$) и $y_i > 0.3$ и $\dot z_i > a_{model}+0.5$; торможение ($u_f<-1$) и $y_i<-0.3$ и $\dot z_i < a_{model}-0.5$ | $L_{slip}\times3$ |
| 5 | аномальная дисперсия | дисперсия невязки в окне 20 измерений $> 0.05$ (м/с)² | $L_{slip}\times2$ |
| 0 | **консенсус** (обратный признак) | обе тележки свежие, согласованы, ускорение правдоподобно; либо единственная исправная тележка с правдоподобной динамикой | $L_{grip}\times20$, раздувание $P_{vv} \leftarrow \max(P_{vv}, y^2)$ |

Правило 0 введено по результатам проверки: при трогании со стоянки и при ошибке модели
(например, выбег на уклоне с ручкой в 0) согласованные датчики не должны отбрасываться —
ошибается модель, а не одометрия (адаптивный Калман с «забыванием»).
Правило 1 опирается на физику: при тяге колесо не может вращаться медленнее трамвая, а
заблокироваться может только при торможении; поэтому оно не зависит от текущей оценки
(которую залипший канал сам тянет вниз — найдено unit-тестом).

### 3.2 Логика переключения доверия «модель ↔ одометрия»

- $P(\text{fault}) > 0.5$ или $P(\text{slip}) > 0.9$ или (NIS $> 100$ и $P(\text{grip}) < 0.5$)
  → измерение тележки **не используется**;
- иначе обновление с $R_{eff} = R_0 / \max(P(\text{grip}), 10^{-3})$ — чем выше вероятность
  скольжения, тем меньше вес (робастный/адаптивный Калман);
- обе тележки не используются → режим `dead_reckoning`: скорость ведётся только моделью
  привода и динамики, дисперсия $P_{vv}$ растёт ($q_v$), при возвращении датчиков оценка
  восстанавливается.

## 4. Оценщик состояния (1.4)

### 4.1 Вектор состояния

$$x = [\,v,\ s,\ d,\ b_f,\ b_r,\ \mu,\ c\,]^T$$

| | смысл | ед. | $P_0$ | шум процесса $q$ (на 1 с) |
|---|---|---|---|---|
| $v$ | продольная скорость base_link | м/с | 1 | 0.04 (0.30 без ручки) |
| $s$ | координата вдоль маршрута (в домене фильтра) | м | 0.01 → 25 после выставки | 1e−4 |
| $d$ | возмущение (уклон + ошибка модели) | м/с² | 0.05 | 0.01 |
| $b_f, b_r$ | ошибка масштаба тележки | — | 1e−5 | 1e−9 |
| $\mu$ | коэффициент сцепления | — | 0.01 | 1e−5, релаксация к 0.2 (τ = 300 с) |
| $c$ | общая ошибка масштаба одометрии | — | 2.5e−5 | 1e−10 |

Положение на маршруте: $s_{route} = s + s_{offset}$ ($s_{offset}$ — из начальной выставки).

### 4.2 Почему EKF (а не UKF)

Нелинейности гладкие (кроме $\max(0,\cdot)$ на стоянке), размерность 7, измерения скалярные.
EKF с численным якобианом (центральные разности) даёт точность, сопоставимую с UKF, при
7 вызовах модели вместо 15 сигма-точек и детерминированном времени ~3–5 мкс на событие.
Обновления скалярные → нет обращения матриц; ковариация обновляется в форме Джозефа
(численная устойчивость). Матрицы 7×7 — свой шаблон без Eigen (сборка без внешних
зависимостей).

### 4.3 Шаги фильтра

**Predict** (при каждом событии, шаг ≤ 50 мс): $x^- = f(x, u_f, \Delta t)$ (разд. 1–2),
$F = \partial f/\partial x$ численно, $P^- = F P F^T + Q\Delta t$.

**Update по тележкам**: модель из разд. 3, вероятностно-взвешенная $R_{eff}$.

**Псевдоизмерение** $b_f + b_r = 0$ ($R = 10^{-8}$): общая мода $b$ ненаблюдаема и
вынесена в отдельное состояние $c$.

**Оценка сцепления $\hat\mu$**: (а) продемонстрированное сцепление — нижняя граница:
если $(|\hat a| + r)/g > \hat\mu$, то обновление к этому значению; (б) при скольжении
(любая тележка $P(\text{slip}) > 0.5$, ручка $|u_f|>1$) передаваемая сила равна $\mu N$,
поэтому $z_\mu = (|\hat a| + r(v))/(g k_{adh})$ — прямое измерение $\mu$ ($R = 0.02^2$).

**Update по ориентирам** (повторяемые места остановок, разд. 5.3):
$z = s_{lm} - s_{offset}$, $H = e_s$, $R = \sigma_{lm}^2 + \sigma_{stop}^2$.
Через корреляции $s \leftrightarrow v \leftrightarrow c$ фильтр оценивает общий износ
колёс $c$ между ориентирами — это вторая онлайн-адаптация (масштаб одометрии).

### 4.4 IMM-режимы (диагностика, критерий 3)

Для каждой тележки поддерживаются вероятности трёх гипотез модели измерения
$\{grip, slip, fault\}$ (IMM-подобная схема с общей динамикой):

$$p^-_j = \sum_i \Pi_{ij}\, p_i, \qquad
p_j \propto p^-_j\, L_j(y), \qquad
\Pi = \begin{pmatrix}0.98 & 0.015 & 0.005\\ 0.10 & 0.88 & 0.02\\ 0.02 & 0.01 & 0.97\end{pmatrix}$$

$L_{grip} = \mathcal N(y; 0, S)\cdot e_{grip}$, $L_{slip} = \mathcal N(y; 0, S + \sigma_{slip}^2)\cdot e_{slip}$
($\sigma_{slip} = 1.5$ м/с), $L_{fault} = \tfrac{1}{30}\cdot e_{fault}$ (равномерная плотность
на 0–30 м/с); $e_\bullet$ — множители признаков из 3.1; $S = HPH^T + R_0$ (χ²-нормировка).
Итоговый режим: `normal_grip` (обе grip), `slip_detected`, `sensor_fault` (fault или нет
сообщений > 0.6 с), `dead_reckoning` (ни одной годной тележки).

## 5. Положение

### 5.1 Карта маршрута

`maps/route_closed.json` (формат pathgraph + поле `segments`): обе полилинии pathgraph без
изменений + **разворотные петли на конечных, восстановленные офлайн** по GNSS-трекам
обучающих прогонов (`tools/build_route.py`: подход к конечной + отправление следующего
рейса сшиваются на одном пути, стык 0.03–0.5 м). Итог — замкнутый маршрут 11 071 м.
Без петель трамвай ~25 % времени находится вне pathgraph, где без курса (нет IMU)
2D-счисление невозможно. `map.use_closed_route:=false` — работа только на исходном
pathgraph (за концами — экстраполяция по касательной).

### 5.2 Два варианта публикации положения

Оба реализованы и публикуются одним сообщением:
1. **Дистанция вдоль пути** $s_{route}$ (в `/result/slip_status` и `/diagnostics`);
2. **Декартовы координаты** в кадре `map` (как у эталона жюри) — точка полилинии на дуге
   $s_{route}$: $(x, y, z) = \Gamma(s_{route})$, курс = касательная. Высота берётся из карты.
Проекция на ближайший сегмент используется при выставке и в метриках (cross-track).

**Ковариация позы** в `nav_msgs/Odometry`: продольная дисперсия $P_{ss}$ поворачивается
в кадр карты, поперечная — $\sigma_{lat}^2$ (0.3 м, точность карты):
$\Sigma_{xy} = R(\psi)\,\mathrm{diag}(P_{ss}, \sigma_{lat}^2)\,R(\psi)^T$; `twist.covariance[0]` $= P_{vv}$.

### 5.3 Начальная выставка и ориентиры

- **GNSS (только первые секунды)**: фикс master → UTM → map; курс — по двум антеннам
  (rover впереди master на 12.4 м), иначе по перемещению, иначе по касательной ближайшего
  пути (точность GNSS 0.2–1 м ≪ межпутье 3.5 м). Точка base_link = антенна − R(ψ)·рычаг
  (tf антенн). Проекция на маршрут с проверкой курса (выбор пути нужного направления).
  Смещение $s_{offset}$ = медиана $(s_{proj,i} - s_{filter}(t_i))$ за окно 5 с — фиксы в
  движении тоже используются, т.к. компенсируются пройденным по одометрии путём.
  После окна GNSS игнорируется (`gnss.correction: false`).
- Резерв: `init.mode: fixed_xy | fixed_s | relative` (без GNSS — через `init.timeout`).
- **Ориентиры** (`maps/stations.json`, `tools/build_stations.py`): 31 место, где трамвай
  повторяемо останавливается (станции и стоп-линии), разброс ≤ 1 м. При подтверждённой
  стоянке ≥ 3 с (обе тележки = 0) и пробеге ≥ 30 м после прошлой привязки — обновление
  $s$, если в гейте ±8 м ровно один ориентир и χ² < 25. Используются только одометрия и
  статическая карта.

## 6. Временная модель и обработка входов

- Фильтр событийный: время фильтра = максимум из штампов обработанных сообщений; выход
  штампуется этим временем (требование судьи: штамп = время входа из bag).
- Сообщения старше времени фильтра до 0.5 с применяются с компенсацией запаздывания
  ($\hat a\,\ell$); старше — отбрасываются; скачок времени назад > 2 с → полный сброс
  (перезапуск bag).
- Отбраковка входа: NaN/Inf, отрицательные, > 30 м/с, |ручка| > 100.
- Публикация: по каждому входу (не чаще 50 Гц по времени данных) + таймер 25 мс (40 Гц):
  между входами публикуется экстраполяция **копии** фильтра не более чем на 0.1 с; при
  пропаже всех входов — до 2 с (watchdog_max_extrapolation). Состояние фильтра таймер не
  меняет.
- **Калибровка временного сдвига**: эталон жюри /localization/kinematic_state запаздывает
  относительно штампов тележек на 0.08–0.10 с (установлено по проверочному bag; GNSS-скорость
  датасета такого сдвига не имеет). Под штампом T публикуется состояние на T − publish.time_offset
  (0.08 с) — интерполяция по истории состояния за 2 с; для эталона без запаздывания — 0.
