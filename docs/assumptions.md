# Допущения, ограничения и конфигурируемые параметры

## 1. Допущения

### Известно и постоянно
1. **Единицы входа**: скорость тележек — км/ч (установлено по данным, вопреки README
   датасета, где указаны м/с). Коэффициент `input.wheel_unit_scale = 1/3.6`.
2. **Кадр эталона** `map` = UTM зона 37N минус (300000, 6100000) м, высота ≈ высота GNSS
   − 0.14 м. Установлено офлайн по проверочному bag (остаток 0.2–0.3 м).
3. **Геометрия маршрута** = pathgraph (1 м шаг) + восстановленные офлайн разворотные петли.
   Трамвай всегда находится на этом маршруте и движется по нему в направлении полилинии.
4. **base_link** — ось поворота передней тележки на уровне головки рельса; положение
   публикуется для этой точки (как у эталона). Рычаги антенн: master (−9.873, 0, 3.0),
   rover (2.563, 0, 3.0) м; база тележек 7.55 м (не используется: положение 1D).
5. Движение **только вперёд** (v ≥ 0): датчики беззнаковые, реверс в линейной
   эксплуатации не встречается в данных.
6. Ручка: целые позиции −15…+15, связь позиция → сила монотонна; одинаковая
   характеристика для обоих вагонов (30618, 30639).
7. Датчики тележек синхронны с точностью до штампа; задержка доставки ≤ 0.5 с.

### Оценивается онлайн
- скорость $v$, координата вдоль пути $s$;
- возмущающее ускорение $d$ (уклон, кривые, ветер, ошибка модели) — медленное (τ = 30 с);
- масштабные ошибки тележек $b_f, b_r$ (относительные) и общий масштаб одометрии $c$
  (износ колёс; наблюдаем через ориентиры-остановки);
- коэффициент сцепления $\mu$;
- коэффициенты эффективности привода $\kappa_t, \kappa_b$ (≈ $m_0/m_{eff}$: загрузка,
  инерция вращающихся масс) — RLS;
- вероятности режимов каждой тележки (grip / slip / fault).

### Приближения (где физика упрощена)
- Удельные силы (на единицу массы): абсолютная масса не наблюдаема; её изменение
  поглощается $\kappa$. Сила/момент в диагностике — через номинальные `mass_kg`,
  радиус, передаточное число (значения типовые для низкопольного трамвая, не из данных).
- Тяговая характеристика — гладкая аналитическая аппроксимация (постоянная сила →
  постоянная мощность), без моделирования электромагнитных переходных процессов;
  динамика привода — звено 1-го порядка (τ = 0.3 с).
- Сопротивление: полином 2-й степени по скорости; уклон и кривые не моделируются
  явно, а входят в возмущение $d$.
- Сцепление: 1D «линейно-насыщающаяся» кривая вместо полной Magic Formula;
  ограничение силы $\mu g k_{adh}$ одно для тяги и торможения.
- Одна жёсткая масса (сочленённость вагона не учитывается).
- Положение — 1D по карте: поперечная ошибка = точность карты (σ ≈ 0.3 м) при
  правильном выборе пути; на многопутных конечных выбор пути (стрелки) ненаблюдаем.
- Места остановок (станции, стоп-линии) повторяемы с точностью ~1 м.

## 2. Ограничения

1. **Разветвления на конечных**: у Таллинской несколько параллельных путей-платформ; в
   карте один вариант (самый частый). Если трамвай идёт по другому — ошибка положения
   до ~50 м на этом участке (видно в конце проверочного bag). Без курса/IMU ненаблюдаемо.
2. **Выход за маршрут** (депо, объезды): положение продолжается по карте — ошибка растёт.
3. **Начальная выставка требует GNSS в первые секунды** (либо заданной начальной точки).
   Без неё — относительная одометрия в кадре `odom` (x = пройденный путь).
4. **Масштаб одометрии** между ориентирами: неучтённый износ колёс (у отдельных прогонов
   до 1.5 %) даёт дрейф до ~1.5 % пройденного пути до ближайшей остановки-ориентира.
5. **Проскальзывание обеих тележек одновременно** с физически правдоподобным ускорением
   неотличимо от реального движения (консенсус датчиков); распознаются только скачки
   ускорения > 2.5 м/с² и расхождение с моделью.
6. В окружении проверочного гарнесса (`check-code-with-bag`) пакет `tram_vehicle_msgs`
   не содержит `DriverControllerCommand` → `ros2 bag play` не публикует ручку; нода
   собирается и работает без неё (модель без тяговой составляющей, больше $q_v$).
   Точность в этом режиме почти та же (одометрия качественная), но модель слабее
   при отказах датчиков.
7. Карта станций/петель построена по данным этого маршрута; для другого маршрута нужно
   перестроить (`tools/build_route.py`, `tools/build_stations.py`).
8. Ресурсы в ROS измерены в гарнессе жюри (Docker, ROS 2 Humble): CPU ≈ 1.1 % ядра,
   RSS ≤ 36 МБ (`validation.md` §5.1); на другом железе значения могут отличаться.

## 3. Конфигурируемые параметры (`config/params.yaml`)

### Топики, кадры, публикация
| Параметр | По умолчанию | Описание |
|---|---|---|
| `topics.front` / `topics.rear` / `topics.command` | `/vehicle/...` | входные топики |
| `topics.gnss_master_fix` / `topics.gnss_rover_fix` | `/sensing/gnss/.../fix` | GNSS для выставки |
| `topics.velocity_out` / `topics.position_out` | `/result/velocity`, `/result/position` | выходы (типы по контракту судьи) |
| `topics.status_out` | `/result/slip_status` | JSON-статус (режим, μ̂, вероятности, λ) |
| `frames.map` / `frames.base_link` / `frames.relative` | `map` / `base_link` / `odom` | frame_id выходов |
| `publish.min_period` | 0.02 с | минимальный интервал выходов (≤ 50 Гц) по времени данных |
| `publish.timer_period` / `timer_max_extrapolation` | 0.025 / 0.1 с | таймер публикации 40 Гц между входами (экстраполяция копии фильтра) |
| `publish.watchdog_max_extrapolation` | 2.0 с | экстраполяция при пропаже всех входов |
| `publish.time_offset` | 0.08 с | [calib] сдвиг к временной шкале эталона `kinematic_state`; 0 для GNSS-эталона |
| `publish.diagnostics_period` | 0.2 с | `/diagnostics`, `/result/slip_status` |

### Карта и начальная позиция
| Параметр | По умолчанию | Описание |
|---|---|---|
| `map.use_closed_route` | true | замкнутый маршрут с петлями / только pathgraph |
| `map.files` | [] | явный список файлов карты (формат pathgraph) |
| `map.landmarks_file` | maps/stations.json | ориентиры-остановки |
| `map.lateral_sigma` | 0.3 м | поперечная σ в ковариации позы |
| `init.mode` | gnss | gnss / fixed_xy / fixed_s / relative |
| `init.x`, `init.y`, `init.yaw` | NaN | начальная точка для fixed_xy и резерв без GNSS |
| `init.path`, `init.s` | 0, 0 | для fixed_s |
| `init.window` / `init.min_fixes` | 5 с / 3 | окно усреднения GNSS |
| `init.timeout` | 15 с | ожидание GNSS до перехода в резерв |
| `init.max_lateral` | 200 м | максимально допустимое удаление фикса от маршрута |
| `init.sigma_s` | 5 м | σ вдоль пути после выставки |
| `gnss.master_*`, `gnss.rover_*` | tf антенн | рычаги антенн в base_link |
| `gnss.correction` | false | использовать GNSS после выставки (по умолчанию нет) |
| `gnss.utm_zone`, `gnss.map_offset_*` | 37, 300000, 6100000, −0.14 | WGS84 → map |
