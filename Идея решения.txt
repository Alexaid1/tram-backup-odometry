Идея решения: адаптивная модель движения трамвая + робастный оценщик состояния

Общая архитектура — гибрид "физическая модель + адаптивная фильтрация":

1. Базовая физическая модель (numerator)

Строим динамическую модель трамвая как объекта управления:

Вход: положение ручки контроллера (задаёт тяговое/тормозное усилие через известную тяговую характеристику двигателя)
Продольная динамика: m·dv/dt = F_тяги(u) − F_сопр(v) − F_уклона − F_скольжения
Модель скольжения колёс — ключевая нелинейность: используем упрощённую Magic Formula (Pacejka) или модель Крайхуса для связи проскальзывания λ = (ω·r − v)/v с силой сцепления, с адаптивным коэффициентом сцепления μ, который зависит от погоды (осадки, температура — если есть внешние данные, иначе оценивается онлайн).
2. Адаптивный оценщик (ядро решения)

Так как параметры (масса с пассажирами, μ, износ колёс) — переменные и неопределённые, чистая модель не годится напрямую. Предлагается Unscented Kalman Filter (UKF) или Extended Kalman Filter с адаптацией параметров, объединяющий:

Модельное предсказание скорости по ручке контроллера (predict step)
Коррекцию по одометрии (measurement update), с весами, зависящими от достоверности каждого колёсного датчика
Дополнительный банк параллельных фильтров (Interacting Multiple Model, IMM) — режимы "нормальное сцепление / скольжение / занос / отказ датчика" — переключение между режимами по невязкам (residuals)
3. Обнаружение отказов датчиков (FDI)
Кросс-валидация показаний одометрии по 4 (или более) колёсам между собой
χ²-тест по невязкам UKF — если один канал даёт статистически невероятное значение, он исключается из обновления, а фильтр продолжает работать на модели + оставшихся датчиках
Онлайн-оценка коэффициента сцепления как дополнительного состояния (расширенный вектор состояния: [v, x, μ, смещение_датчика])
4. Компенсация скольжения

Отдельный блок сравнивает "модельную" скорость (из тяги) со "скоростной по колёсам" — расхождение = признак проскальзывания. Используется как:

признак для IMM-переключения режима
вход для корректировки μ в реальном времени (градиентная адаптация/RLS)
5. ROS 2 Humble реализация
tram_control_listener — подписка на топик положения ручки контроллера
wheel_odometry_node — агрегация и предобработка сигналов одометрии (фильтрация выбросов)
motion_model_node — физическая модель + предсказание (C++, real-time critical path)
state_estimator_node (UKF/IMM) — на C++ для детерминированного времени выполнения, публикует /tram/odom_estimated (nav_msgs/Odometry) и /tram/velocity_estimated
fault_diagnosis_node — публикует статус датчиков /tram/sensor_health
Использование rclcpp с real-time executor (либо ros2_control real-time safe loop), частота публикации 50–100 Гц, жёсткий deadline
6. Обучаемая компонента (опционально)

Параметры модели (μ, коэффициенты сопротивления) можно доуточнять офлайн через небольшую NN/gaussian process поверх физической модели (residual learning) — физика даёт грубую оценку, сеть компенсирует систематическую ошибку, что даёт лучшую генерализацию при малых данных, чем чистый ML-подход, и сохраняет интерпретируемость для сертификации безопасности.

Ключевой тезис для презентации: не "чёрный ящик"-предсказатель, а физически интерпретируемая модель с адаптивной байесовской фильтрацией и явной диагностикой отказов — это критично для сертификации автономного транспорта.
